# v0.0 contracts

Written 2026-10-12, before any v0.0 app code. Three pieces of v0.0 (the API, the web app, the deploy files) were built at the same time by three separate workers. If each had picked its own port, its own name for the database setting or its own error shape, they wouldn't have fitted together. So the shared names were fixed first, in one small change, and every worker was told to follow it. This note is that list.

A **contract** here just means "a promise two pieces of code make to each other": *the API will answer `/healthz` with exactly these fields, and the web app may rely on them*.

## Package names

| Folder | Package name | What it is |
|---|---|---|
| `packages/core` | `@tasks/core` | Pure shared code (already existed) |
| `apps/api` | `@tasks/api` | The Hono server |
| `apps/web` | `@tasks/web` | The React PWA |

## Scripts (run from the repo root)

| Script | What it does |
|---|---|
| `pnpm dev` | Starts Postgres in Docker (`docker compose up -d --wait db`), then the API and the web dev server side by side |
| `pnpm build` | Builds every package that has a build step (only the web app: `vite build` → `apps/web/dist`) |
| `pnpm start` | Starts the API the production way |
| `pnpm db:migrate` | Applies database migrations |
| `pnpm typecheck`, `test`, `test:tz`, `coverage`, `check` | As before ([[Repo root and tooling]]) |

The API has no build step: Node 24 runs `.ts` files directly by deleting the type annotations ([[TypeScript checking vs running]]). Checked on 2026-10-12 in the `node:24-alpine` image (Node 24.21.0): it runs a `.ts` file with no flag and no warning.

## Ports

| Port | Who listens | Why |
|---|---|---|
| 5173 | Vite (web dev server) | What you open in the browser during development. It forwards `/api/*` and `/healthz` to the API, so the browser sees **one origin** ([[Origin]]), just like production |
| 3000 | The API | Behind Vite in development, behind Caddy in production |
| 5432 | Postgres | Published on `127.0.0.1` only, in the dev `compose.yaml`. The production compose file never publishes it |

## Environment variables

The full list, with comments, is `.env.example` at the repo root. An **environment variable** is a named setting the operating system hands to a program when it starts (`PORT=3000`). Secrets go there instead of into the code, so the code can be public.

| Variable | Meaning |
|---|---|
| `NODE_ENV` | `development`, `test` or `production` |
| `HOST`, `PORT` | Where the API listens |
| `LOG_LEVEL` | How chatty the logs are |
| `DATABASE_URL` | How to reach Postgres |
| `TEST_DATABASE_URL` | A separate database the tests are allowed to wipe |
| `BETTER_AUTH_URL` | The origin the browser sees |
| `BETTER_AUTH_SECRET` | The key that signs session cookies |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | The Google sign-in client |
| `AUTH_ALLOWED_EMAILS` | Who may sign in |
| `GIT_SHA` | Which commit is running (shown by `/healthz`) |
| `STATIC_DIR` | Where the built PWA is, for the API to serve in production |

In development every variable has a safe default, so a fresh clone runs without a `.env` file. In production the important ones are required, and the server refuses to start without them.

## HTTP shapes (`packages/core/src/api.ts`)

- `GET /healthz` → `{ sha, dbOk, time }`. Public. Status 200 if the database answered, 503 if not.
- `GET /api/v1/me` → `{ user: { id, email, name, image }, profile: { tzid, dayBoundary }, serverTime }`. Needs a session.
- Every error → a **problem** body (RFC 9457): `{ type, title, status, code, detail?, requestId, errors? }`, sent as `application/problem+json`. `code` is one of `unauthenticated`, `forbidden`, `not_found`, `malformed_request`, `validation_failed`, `internal_error`.

**Why put these in `core`?** Both the API (which sends them) and the web app (which reads them) import the same TypeScript types. If someone renames `serverTime` on one side, the other side stops type-checking. That's D-015's "names decided once", applied to the network.

**Why snake_case codes** (`not_found`, not `not-found` or `NotFound`)? The rest of `core` already spells stored values that way (`not_held`, `manual_entry`), so there's one style to remember.

**Why only types, not zod schemas?** v0.0 has no request bodies of its own; sign-in is Better Auth's. Zod schemas arrive in v0.2 with the first real inputs (creating a series).

## Check yourself
- You run `pnpm dev` and open `http://localhost:5173/healthz`. Which program answers first, and which one actually produces the JSON?
- Why does the dev setup bother forwarding `/api` through Vite instead of letting the browser call `localhost:3000` directly? (Hint: [[Origin]] and cookies.)
- The web app reads `me.serverTime`. Someone renames it to `now` in the API's code only. Where does the mistake get caught: at typecheck, in a test, or only in your browser?
